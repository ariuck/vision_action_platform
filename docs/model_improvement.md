# 사용 모델과 성능 개선 기록

이 서비스는 무인 상점 이상행동 17개를 분류하는 3팀 동작 인식 모델을 사용한다.
모델 학습과 실험 원본은 [`ariuck/subject10_pose_action`](https://github.com/ariuck/subject10_pose_action) 레포에 있다.
이 문서는 서비스에 넣은 모델이 어떻게 만들어졌고, 성능을 올리려고 무엇을 했는지 정리한 것이다.

> 교재의 기본 모델은 6개 일상 동작(`bend_return` 등) Random Forest다.
> 이 프로젝트는 팀에서 직접 촬영·라벨링한 17개 이상행동 모델을 쓰기로 했다. 서비스 목적이 무인 상점 이상행동 감지라서, 그 상황에 맞는 동작을 다루는 모델이 필요했다.

## 1. 모델 개요

| 항목 | 내용 |
|---|---|
| Pose | YOLO11n-pose (COCO 17 관절) |
| Frame Feature | 45-D = 관절 정규화 좌표 34 + 관절각도 4 + 팀 Feature 7 |
| 팀 Feature 7개 | 상체 기울기, BBox 가로/세로 비율, 골반-바닥 높이, 왼·오른발목 속도, 왼·오른손목 속도 (속도는 0.1초 간격, 상체 길이로 나눔) |
| Sequence | **동작 구간만** 잘라 30 Step으로 맞춤 → 30 × 45 = 1,350 Feature (7번 참고) |
| 분류기 | Random Forest 300 Tree, class_weight balanced |
| 동작 | 17개 (A001 키오스크 두드리기 ~ A017 앞으로 넘어지기) |
| 학습 데이터 | 사람·동작마다 4개: 정면 + 측면 + 측면 좌우 반전 + 후면 → 5명 전체 340개 (원본 255 + 반전 85) |
| 예상 성능 | 처음 보는 사람 기준 Accuracy 약 0.78 (5명 교차 평가 평균 **0.784**, 범위 0.745~0.824) |

## 2. 데이터

| 항목 | 내용 |
|---|---|
| 사람 | 5명 (가명 ID S01~S05) |
| 촬영 방향 | T01 정면 / T02 측면 / T03 후면 |
| 영상 | 255개 (5명 × 17동작 × 3방향), Pose 성공 99.7% |
| 품질 확인 | 자동 QA + 확인 사진으로 255개 모두 직접 확인 |
| 증강 | 측면 85개를 Keypoint 단계에서 좌우 반전 (학습 사람 것만 학습에 사용) |

## 3. 성능을 올리려고 한 일

모든 단계에서 모델 설정은 같고, 바꾼 것은 Feature와 학습 데이터 구성뿐이다.

```text
① 교재 38-D Feature
② 팀 Feature 7개 추가 → 45-D
③ 측면 좌우 반전 증강
④ 후면 Take 추가 (정면·측면 → 정면·측면·후면)
⑤ 5명 교차 평가로 ③·④ 효과 재확인
⑥ 동작 구간만 잘라 학습·예측 (카메라 테스트 후, 7번)
```

### 5명 교차 평가 결과

5번 학습한다. 매번 한 명을 Test로 빼고 나머지 4명으로 학습한 뒤, 빠진 사람의 원본 영상 51개(정면·측면·후면)로 평가한 평균이다.

| Feature | 학습 데이터 (사람·동작당) | 평균 Accuracy | 정면 | 측면 | 후면 | 평균 Confidence |
|---|---|---:|---:|---:|---:|---:|
| 38-D | 정면 + 측면 (2개) | 0.557 | 0.718 | 0.682 | 0.271 | 0.293 |
| 45-D | 정면 + 측면 (2개) | 0.635 | 0.847 | 0.776 | 0.282 | 0.290 |
| 45-D | + 후면 (3개) | **0.761** | 0.765 | 0.753 | **0.765** | 0.303 |
| **45-D** | **+ 후면 + 측면 반전 (4개)** | 0.753 | 0.776 | 0.765 | 0.718 | **0.325** |

### 무엇이 효과가 있었나

| 시도 | 효과 | 근거 |
|---|---|---|
| 팀 Feature 45-D | ✅ 있음 | 모든 구성에서 38-D보다 7~10%p 높음 |
| 후면 Take 추가 | ✅ 가장 큼 | 전체 0.635 → 0.761, 후면 0.28 → 0.77. 다섯 사람 모두 상승 |
| 측면 좌우 반전 | ➖ 정확도 효과 없음 | 0.761 → 0.753, 사람 간 차이(약 0.05)보다 작음. Confidence는 0.303 → 0.325로 상승 |

- 후면을 넣자 정면 정확도는 0.847 → 0.765로 조금 떨어졌다. 카메라가 사람 뒤쪽도 찍는 매장 환경을 생각해 후면을 포함했다.
- 한 사람으로만 평가했을 때는 "후면 + 반전"이 Test 0.765로 가장 좋아 보였지만, 5명 평균에서는 "후면만 추가"와 같은 수준이었다. 사람 한 명 점수로 증강 효과를 판단하지 않았다.

## 4. 최종 모델 선택 이유

- 정확도는 "후면만 추가"(0.761)와 "후면 + 측면 반전"(0.753)이 사실상 같다.
- "후면 + 측면 반전"은 Confidence가 가장 높다. 서비스에서 Confidence 기준을 넘는 예측이 더 많이 나와, UNKNOWN으로 보류되는 경우가 줄어든다.
- 측면 카메라가 반대쪽에 달린 매장도 대비할 수 있다.
- 구성을 정한 뒤 서비스용 모델은 **5명 전체 데이터(340개)로 다시 학습**했다. 평가에 쓸 사람이 남지 않으므로, 처음 보는 사람에 대한 성능은 같은 구성의 5명 교차 평가 평균(0.753)으로 본다.

## 5. 서비스에서 주의할 점

- 모델 입력은 45-D Feature다. 교재 실시간 코드는 38-D만 계산하므로, AI 서버의 Feature 계산에 팀 Feature 7개(속도는 0.1초 간격)를 함께 넣어야 한다.
- 17개가 모두 이상행동이고 정상행동 데이터가 없다. 평범하게 서 있는 사람도 17개 중 하나로 예측될 수 있으므로, 결과는 Confidence와 함께 보여 주고 이상행동으로 확정하지 않는다.
- 팔로 하는 동작끼리(밀치기 ↔ 잡고 흔들기 ↔ 샷건) 헷갈림이 남아 있다. 물체 위치 정보 없이 Pose만으로는 구분이 어렵다.
- 모델 파일(`.joblib`, 약 9MB)과 YOLO 가중치(`.pt`)는 Git에 올리지 않는다. `subject10_pose_action/artifacts/team03/day06/team_45d_segment_3view_hflip_all5/`의 세 파일(`rf_action_baseline.joblib`, `rf_feature_columns.json`, `rf_training_info.json`)을 AI 서버의 모델 폴더로 복사해서 쓴다. 다시 만들 때는 `subject10_pose_action`에서 `python scripts/team03/team_train_final_all.py --segment`를 실행한다.
- `rf_training_info.json`의 `segment_only`가 `true`면 AI 서버도 같은 규칙으로 동작 구간을 잘라서 넣는다. 예전 모델(`segment_only` 없음)을 넣으면 자르지 않는다.

## 7. 동작 구간만 잘라 쓰기 (카메라 테스트 뒤 추가)

**왜 했나**: IP Webcam은 8초를 녹화하는데, 그 안에 준비하며 서 있는 시간이 섞인다. 30 Step으로 줄이면 동작 부분이 작아져서 예측이 흔들렸다. 학습 영상은 동작 직전부터 직후까지만 찍혀 있다 (길이 중간값 5.4초).

**어떻게 자르나**: 학습 데이터 동작 구간을 정할 때 쓴 규칙 그대로 (`team_action_segments.py`)
- 관절 12개가 0.1초 동안 움직인 평균 거리 ÷ 상체 길이 → 0.5초 이동 평균
- 하위 5% ~ 상위 95% 사이 20% 높이를 기준선으로, 처음·마지막으로 넘은 곳 ± 0.2초

**실험 (5명 교차 평가, 45-D, 후면 + 측면 반전 구성)** — `team_loso_segment.py`

| 방법 | 평균 Accuracy | Macro F1 | 가장 낮은 사람 | 사람 간 차이(std) | 판단 |
|---|---:|---:|---:|---:|---|
| A. 전체로 학습 → 전체로 예측 (기존) | 0.753 | 0.751 | 0.686 | 0.049 | |
| B. 전체로 학습 → **예측할 때만** 자르기 | 0.722 | 0.695 | 0.647 | 0.061 | ❌ 되돌림 |
| C. **구간으로 다시 학습** → 구간만 예측 | **0.784** | **0.775** | **0.745** | **0.031** | ✅ 채택 |

- B가 나빠진 이유: 모델은 앞뒤 대기 시간이 섞인 모양으로 학습했는데, 예측 때만 잘라서 넣으니 입력 모양이 학습 때와 달라졌다. 학습과 예측은 같은 방식으로 맞춰야 한다는 걸 다시 확인했다.
- C는 평균이 3.1%p 오르고, 가장 낮은 사람도 0.686 → 0.745로 올라 사람에 따라 덜 흔들렸다.
- 6일차(38-D, 사람 1명 검증)에서도 구간만 쓰면 오답이 13개 → 9개로 줄었었다. 이번에 45-D·5명 평가로 같은 방향을 다시 확인했다.

**서비스 반영**
- 5명 전체 340개를 구간만으로 다시 학습 → `team_45d_segment_3view_hflip_all5`
- AI 서버도 같은 규칙으로 자르게 했다. 학습 코드와 비교한 결과 S05 30개 영상에서 잘린 구간이 같고, 1,350개 숫자 최대 차이 0.000008 (반올림 수준).
